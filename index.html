Operations Analytics Architecture

Building a scalable operational tracking and reporting architecture as project volume and information complexity grew.

Systems design Smartsheet Process
Explore case study ↗

Context: Operational tracking needed to scale with project volume, stakeholders and data requirements.

Approach: Structure information architecture, standardise key fields and workflows, and develop views for operational follow-through.

Evolution: Approximately 40 projects / 16 data points; then 200 / 100; and later 700 to 800+ active projects / 250+ data points.

Learning: Scaling a tracker is not simply adding columns. It requires clear definitions, governance, adoption and a connection between information and action.

Predictive Manpower Planning

A planning model concept to translate upcoming installation workload into indicative carpenter demand.

Forecasting Capacity planning Model design
Explore case study ↗

Context: Installation capacity planning depends on upcoming workload, productivity and project duration.

Approach: Translate project-level facia area into indicative carpenter demand using assumed productivity and a standard installation window.

Illustrative assumptions: 20 sq ft per carpenter per day, a six-day installation cycle and two additional mandays for segregation per project.

Status: Model concept, not a validated forecast. Assumptions require calibration against historical productivity and actual completion data.

Learning: A forecast is only as useful as its assumptions, input quality and feedback loop.
